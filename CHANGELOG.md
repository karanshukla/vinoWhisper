## [0.5.0] - 2026-09-13

### 🐛 Bug Fixes

- **Words no longer print twice when the decoder changes its mind about
  them.** The hop is 0.7s in practice, so the last confirmed word is about a
  second from the window's edge, and two near-identical windows would agree
  on a spelling Whisper then abandoned ("Whispers", then "Whisper's"). The
  stitcher could not match the new spelling against the printed one and
  printed it again. It now recognises a re-decode of what it already printed
  and skips it. Two more stitcher bugs went with it: the boundary check from
  0.3.1 only worked while the transcript fit in one window, and a stall long
  enough for the confirmed words to leave the window never recovered. All
  three measured on real NPU decodes of recorded speech, the first such
  recordings this project has had; one is now a test fixture. See
  `docs/latency.md`.
- **A fresh install gets past the model step.** The dependency set resolved
  transformers 5.5.4, whose NPU export builds and then fails at `generate()`,
  so `vinowhisper-setup` stopped at the model step on every new machine. The
  export tooling is now its own extra, `vinowhisper[export]`, holding
  `transformers<5.4`, and the wizard offers it when it needs to export. The
  default install no longer carries optimum or torch, which only the one-time
  export ever used. See `docs/install.md`.
- **The GPU fallback can be diagnosed, and hardware OpenVINO cannot drive is
  named.** OpenVINO's device list cannot tell "no GPU" from "an Intel GPU with
  no compute runtime", and this laptop sat in the second case with nothing
  saying so. The doctor and the wizard now read the PCI bus, name a missing
  OpenCL runtime with the install command for your distro, report AMD NPUs and
  AMD or NVIDIA GPUs as present but unusable, and stop offering an Intel NPU
  driver to machines without an Intel NPU. See `docs/hardware.md`.
- **Fedora's install lines named a package that does not exist.** The NPU
  driver and GPU runtime lines both included `level-zero`, which Fedora has no
  package for, so `dnf install -y` failed outright. Each is one package now.

### 🎨 Styling

- **One icon everywhere, and it is the app's own.** The launcher, the tray
  and the README now share one mark: a caption box in the overlay's own
  colours, with green voice bars becoming a word. Until now the launcher had a
  Breeze-blue box and the tray showed the icon theme's stock subtitles icon.
  The tray asks for `io.github.karanshukla.vinowhisper-symbolic`, the same
  mark redrawn in Breeze's style (a one-pixel outline on a 16px grid, voice
  bars in the launcher's green) so it sits with the panel's own icons, and falls
  back to full-colour pixmaps. All of it is generated from `gui/src/icon.rs`,
  and existing installs pick up the new icons on their next launch.

### ⚡ Performance

- **Nothing wakes while the overlay is hidden.** Measured on hardware, the GUI
  woke once a second for a "Starting…" counter it was not showing, and the
  resident server twice a second for `serve_forever`'s shutdown poll, which
  nothing uses. Both are now at zero. A visible overlay no longer redraws on
  silence events that change nothing on screen, which cut its wakeups from 8.7
  to 3.7 a second and spares the compositor a repaint each time. The NPU was
  never the problem: it suspends 100ms after the last inference, loaded model
  or not. See `docs/architecture.md`.

### 📚 Documentation

- **Comments out of the code, notes into `docs/`.** Nearly every comment and
  docstring in `vinowhisper/` and `gui/src/` is gone, about 1,600 lines. The
  few left each guard code that would otherwise invite a wrong fix. What was
  worth keeping moved into the docs page it belongs to, and
  `docs/terminal.md` is new. No code changed: the Python ASTs are identical
  with docstrings stripped, and the Rust differs only in comments.

## [0.4.0] - 2026-09-12

### ✨ Features

- **A floating caption overlay, tray icon and global shortcut**:
  `vinowhisper-gui`, in `gui/`. A Wayland layer-shell box on the overlay
  layer, so it floats above every window including fullscreen video, and it is
  click-through so it never blocks what is under it. The tray menu picks the
  source, position and text size. Meta+Alt+C by default, requested through the
  desktop portal and rebindable from the tray or System Settings. Hiding it
  stops captioning, so the server still scales to zero. Tested on KDE Plasma
  6.7; GNOME has no layer-shell and is refused with a message saying so.
- **Rust, optional, and never on PyPI.** `vinowhisper-setup --gui` downloads a
  static musl binary (6.0MB) from the GitHub release and checks it against the
  sha256 the release workflow pins into the wheel before building it. A
  mismatch installs nothing, and a build with no pin (a source checkout)
  never downloads; it offers a cargo build instead. The Python package gains
  no dependencies, and the terminal UI is unchanged.
- One version for the whole repo: `bump-my-version` now moves
  `gui/Cargo.toml` and its lock entry with `pyproject.toml`, because the wizard
  downloads the overlay from the release tagged with the Python version.
- `vinowhisper-caption --json`: one ASCII-escaped JSON object per event on
  stdout (`events.to_dict`, verbatim), plus an `Error` record when the CLI
  gives up. It is what the overlay reads, and it is there for anything else
  that wants the event stream.

### 🧪 Testing

- The fields the overlay reads are named in `tests/test_caption.py`, so
  renaming one on the Python side fails a test instead of blanking the
  overlay. CI gains a `gui` job: `cargo fmt`, `clippy -D warnings` and 59 unit
  tests, none of which needs a compositor.

## [0.3.1] - 2026-08-31

### 🐛 Bug Fixes

- `release.yml`'s GitHub Release job could not create a release. Splitting the
  workflow into build/publish/release jobs left that job without a checkout, so
  `gh` had no git remote to infer the repository from and exited with `fatal:
  not a git repository`. Fixed with `GH_REPO`, which is what it is for. Found
  cutting v0.3.0: PyPI had already published, so the release was created by
  hand from the same artifacts.

### 📚 Documentation

- PyPI badges in the README. The Python badge is now derived from package
  metadata (`shields.io/pypi/pyversions`) rather than hardcoded, so it cannot
  drift from `requires-python`.

## [0.3.0] - 2026-08-31

### 📦 Packaging

- **Published to PyPI.** `pip install vinowhisper` works for the first time.
  It was withheld until now for a real reason rather than an omission: a pip
  install would have resolved openvino from PyPI, where the builds that can
  construct the NPU static Whisper pipeline did not exist, and something that
  installs and then cannot load a model is worse than nothing. Stable 2026.3.1
  removed that constraint.
- Releases upload via **Trusted Publishing**, so no PyPI API token exists in
  the repo or on a developer machine. `release.yml` is split into build,
  publish and release jobs so the upload never holds a token that can write to
  the repo.
- Error messages no longer name `./scripts/convert_model.sh` unconditionally.
  That file only exists in a git checkout, so an install from a wheel was being
  pointed at a script it did not have. `config.export_command()` now names
  whichever path this install actually has.
- PEP 639 license metadata (`license = "MIT"` plus `license-files`), and README
  links rewritten absolute so they resolve on the PyPI project page.

### 🚀 Features

- `vinowhisper-doctor` now checks the userspace half of the NPU stack: the
  level-zero backend and the graph compiler, each reported with the version
  string embedded in the library itself. This runs whether or not the NPU
  enumerated, because the two failures it catches both leave the device
  visible and fail later inside `compile_model()`. A missing
  `libopenvino_intel_npu_compiler.so` (which no distro packages) prints the
  extraction steps; a soname symlink reverted to an older backend by a package
  reinstall prints the `ln -sf` that undoes it.

### 🔧 Dependencies

- **The OpenVINO nightly pin is gone.** `openvino>=2026.3.1` from PyPI, with
  `[[tool.uv.index]]`, `[tool.uv.sources]` and `prerelease = "allow"` all
  removed. Stable 2026.2.1 could not build the NPU static Whisper pipeline,
  which is why 2026-08-03 pinned nightly wheels; 2026.3.1 can. Measured
  2026-08-31 on the Wildcat Lake NPU against the same `--disable-stateful`
  export: stable 2026.3.1 builds in 2.0s and decodes, as do nightly
  2026.4.0.dev20260805 and 2026.5.0.dev20260831. This removes the project's
  standing dependency risk, since nightly builds are pruned upstream on their
  own schedule and a lock pinning one eventually 404s.

### 📚 Documentation

- README cut from 365 lines to 121. Everything longer than a paragraph moved
  into `docs/`: installing, hardware, audio capture, latency, debugging, and
  architecture. No measured claim was reworded in the move.

## [0.2.0] - 2026-08-13

The release that stops assuming it is running on the machine it was written on.

### 🚀 Features

- Automatic device selection (NPU → GPU → CPU) with a loud, unmissable warning
  wherever it lands below the NPU: the server log, `/health`, a red panel border
  and a `⚠` line on the status bar, and `vinowhisper-doctor`.
- `vinowhisper-setup`, a guided install that checks each step first, phrases
  every fix in the local distro's package names, and generates the systemd
  units against the paths that actually exist — the checked-in unit used to
  hardcode `~/Development/vinoWhisper`.
- `scripts/install.sh`, a one-command bootstrap: uv, checkout, `uv sync`, then
  the wizard.
- PulseAudio capture backend (`parec`), so the tool runs on machines that never
  moved to PipeWire. Per-application `--target` stays PipeWire-only, and says so
  rather than capturing the wrong thing.
- Distro awareness for eight families (Fedora, Debian/Ubuntu, Arch, openSUSE,
  Alpine, Gentoo, Void, NixOS): package names, install commands, and NixOS
  getting configuration advice instead of an imperative command that would not
  persist.
- NPU diagnosis that goes past "no NPU": the `/dev/accel` node, its permissions,
  the `intel_vpu` module, and then the userspace driver package for this distro
  with Intel's release page as the authoritative fallback.
- Two model exports, because the export is device-specific — the
  `--disable-stateful` NPU export cannot run on CPU at all.
  `scripts/convert_model.sh --variant npu|stateful|both`.
- `vinowhisper-doctor --json` for bug reports, `--no-probe` to skip the live
  level capture, and `--version` on every command.

### 🐛 Bug Fixes

- The default sink is now discoverable without `pactl`, by reading PipeWire's
  own `default.audio.sink` metadata — a PipeWire install without
  `pipewire-pulse` was previously unusable for want of one string.
- The server no longer dies inside the pipeline constructor on a mismatched
  model export. It names the variant, the directory and the command to fix it.

### 🧪 Tests

- A test suite, which this project deliberately did not have. 100+ tests, none
  of which need an NPU, an audio server or OpenVINO — every caption bug from the
  2026-08-06 and 2026-08-07 reviews is now a fixture.

### 👷 CI/CD

- CI on 3.11/3.12/3.13: ruff, ruff format, mypy, pytest, shellcheck.
- A weekly dependency canary, kept off the pull-request path: the OpenVINO
  nightly wheels are pruned upstream on their own schedule, so gating PRs on
  them means red CI for reasons unrelated to the change.
- Tag-driven releases, Bandit scanning to code scanning, Renovate, issue and
  PR templates, MIT licence, contributing and security policies.

## [0.1.0] - 2026-08-07
